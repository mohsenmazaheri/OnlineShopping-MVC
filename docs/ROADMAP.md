# نقشهٔ راه و فازبندی پروژهٔ OnlineShopping-MVC

> هدف: فروشگاه اینترنتی **تک‌فروشگاهی برای کسب‌وکارهای کوچک** (تعداد مشتری کم تا متوسط)، سریع، زیبا، امن،
> چندزبانه، با انبارداری و حسابداری، قابل نصب روی هاست ارزان.
>
> هر فاز یک خروجی قابل اجرا و قابل تست دارد. فاز بعدی فقط وقتی شروع می‌شود که «معیار پایان» فاز قبل برآورده شده باشد.
> وضعیت‌ها: ✅ انجام شد · 🔄 در حال انجام · ⬜ شروع نشده

## اصول ثابت در همهٔ فازها

| موضوع | قاعده |
|---|---|
| معماری | Clean Architecture: `Domain` ← `Application` ← `Infrastructure` ← `Web`. وابستگی فقط به سمت داخل. |
| SOLID / Clean Code | هر کلاس یک مسئولیت؛ وابستگی به Interface؛ کنترلرها نازک (فقط فراخوانی سرویس Application)؛ بدون منطق تجاری در View. |
| تست | **برای هر کلاس جدید، تست واحد متناظر** در `tests/`. هیچ PR بدون تست سبز ادغام نمی‌شود. |
| امنیت | هر شناسه‌ای که از URL/فرم می‌آید باید با مالک (کاربر جاری) چک شود — درس IDOR از BulkyWeb. |
| رازها | هیچ کلید/رمزی در Git نیست: `dotnet user-secrets` در توسعه، متغیر محیطی در سرور — درس کلیدهای Stripe در BulkyWeb. |
| بسته‌ها | `dotnet list package --vulnerable --include-transitive` در CI؛ بسته‌های آسیب‌پذیر ترانزیتیو را مستقیم پین کنید. |
| مستندات | هر فاز بخش مربوط به خودش را در `docs/` (کاربر / ادمین / مدیر سیستم) به‌روز می‌کند. |
| کپی‌رایت | الهام از چیدمان و تجربهٔ کاربری فروشگاه‌های بزرگ (مثل دیجی‌کالا) مجاز است، اما **لوگو، نام، رنگ سازمانی، آیکون، تصویر، متن و کد CSS آن‌ها کپی نمی‌شود**. برند، پالت رنگ، آیکون (Bootstrap Icons) و فونت (Vazirmatn — مجوز OFL) مستقل‌اند. |

## فاز ۰ — رفع مشکلات پایه ✅

- ارتقا به **.NET 10 (LTS)** — پشتیبانی .NET 9 در ۱۰ نوامبر ۲۰۲۶ تمام می‌شود.
- حذف کلاس خالی `IdentityUser` که با کلاس Identity هم‌نام بود (همان نوع خطایی که در BulkyWeb باعث خرابی Login/Logout شد).
- حذف نرم (Soft delete) خودکار + فیلتر سراسری کوئری + ثبت خودکار `CreatedUtc`/`ModifiedUtc` با `AuditableEntityInterceptor`.
- دقت `decimal(18,2)` برای همهٔ مبالغ.
- کلید خارجی `CustomerId`/`SellerId` به `AspNetUsers` (سفارش‌ها با حذف کاربر حذف نمی‌شوند).
- ایندکس یکتای فیلترشده برای Slug، SKU، سبد خرید و اقلام سبد.
- Check constraint وضعیت سفارش به‌صورت خودکار از enum ساخته می‌شود.
- Seeder: بدون رمز در کد، خطاهای Identity نادیده گرفته نمی‌شوند، Migration خودکار در Development.
- رفع آسیب‌پذیری بستهٔ ترانزیتیو `System.Security.Cryptography.Pkcs`.
- اولین Migration و پروژهٔ تست واحد (۲۲ تست).

## فاز ۱ — معماری و زیرساخت ⬜

**خروجی:** اسکلت تمیز و قابل توسعه.

- تفکیک Solution:
  `src/OnlineShop.Domain`، `src/OnlineShop.Application`، `src/OnlineShop.Infrastructure`، `src/OnlineShop.Web`،
  `tests/*.UnitTests`، `tests/*.IntegrationTests` (با `WebApplicationFactory`).
- الگوهای Application: سرویس/Use-case، DTO، اعتبارسنجی (FluentValidation)، نتیجهٔ عملیات (`Result<T>`) به‌جای Exception برای خطاهای تجاری.
- لاگ ساخت‌یافته (Serilog)، مدیریت خطای سراسری (`ProblemDetails`)، Health checks.
- Options Pattern با اعتبارسنجی در Startup برای همهٔ تنظیمات.
- GitHub Actions: Build + Test + اسکن بسته‌های آسیب‌پذیر + Coverage.
- پایهٔ امنیتی: HTTPS/HSTS، هدرهای امنیتی (CSP، X-Content-Type-Options، Referrer-Policy، Frame-Options)، Antiforgery سراسری،
  Rate limiting، کوکی‌های `Secure`/`HttpOnly`/`SameSite`، ذخیرهٔ کلیدهای Data Protection.

**معیار پایان:** CI سبز، تست یکپارچه‌سازی که صفحهٔ اصلی و هدرهای امنیتی را چک کند.

## فاز ۲ — هویت و حساب کاربری ⬜

- ورود با **Google، Facebook، Microsoft** و ایمیل/رمز (ASP.NET Core Identity).
- Scaffold صفحات Identity با `AppUser` (نه `IdentityUser` — درس BulkyWeb) و استایل سایت.
- تأیید ایمیل اجباری، بازیابی رمز، **2FA (Authenticator)**، قفل حساب پس از تلاش ناموفق، سیاست رمز قوی (حداقل ۱۲ کاراکتر).
- ارسال ایمیل از طریق `IEmailSender` (SMTP / SendGrid، قابل تعویض).
- نقش‌ها برای فروشگاه کوچک: `Admin`، `Manager`، `Warehouse` (انباردار)، `Accountant` (حسابدار)، `Customer`.
- پروفایل، دفترچهٔ آدرس، حذف/دانلود اطلاعات شخصی (GDPR) — با ناشناس‌سازی سفارش‌ها به‌جای حذف.
- `ClaimsPrincipal.GetUserId()` / `IsStaff()` مثل BulkyWeb برای همهٔ چک‌های مالکیت.

## فاز ۳ — چندزبانگی، تم و سیستم طراحی ⬜

- زبان‌ها: **فارسی (fa)، انگلیسی (en)، ارمنی (hy)، آلمانی (de)، عربی (ar)**.
  - متن رابط کاربری: `IStringLocalizer` با فایل‌های منبع؛ افزودن زبان جدید = افزودن یک فایل منبع + یک ردیف در تنظیمات.
  - محتوای پایگاه داده (نام محصول، توضیحات، دسته): جدول‌های ترجمه (`ProductTranslation` و ...) با Fallback به زبان پیش‌فرض.
  - آدرس‌دهی `/{culture}/...` (برای SEO) + `hreflang`.
  - RTL برای fa/ar با Bootstrap RTL؛ LTR برای en/hy/de.
  - قالب‌بندی تاریخ (شمسی برای fa)، عدد و ارز بر اساس فرهنگ.
- **تم روشن و تیره:** Bootstrap 5.3 `data-bs-theme` + متغیرهای CSS؛ پیش‌فرض بر اساس `prefers-color-scheme`، قابل تغییر و ذخیره.
- سیستم طراحی مستقل: پالت رنگ، فونت، کارت محصول، دکمه‌ها، Skeleton loading، Toast.
- چیدمان الهام‌گرفته از فروشگاه‌های بزرگ ایرانی: هدر با جستجوی بزرگ، مگامنو، اسلایدر، نوار پیشنهاد شگفت‌انگیز با شمارش معکوس، فوتر کامل.

## فاز ۴ — کاتالوگ محصولات ⬜

- دسته‌بندی درختی، **برند**، ویژگی‌ها و مشخصات فنی قابل فیلتر (Attribute / AttributeValue).
- تنوع محصول (رنگ/سایز) با SKU، قیمت و موجودی جداگانه.
- **چند تصویر و ویدئو برای هر محصول** (`ProductMedia`: نوع، ترتیب، متن جایگزین، تصویر اصلی).
  - ذخیره‌سازی پشت `IFileStorage` (دیسک محلی / S3-compatible).
  - امنیت آپلود: بررسی Magic bytes، محدودیت حجم، بازسازی تصویر (حذف متادیتا)، نام فایل تصادفی.
  - تولید خودکار اندازه‌های مختلف و WebP/AVIF، Lazy loading.
  - ویدئو: آپلود MP4 با محدودیت حجم یا لینک Embed.
- پنل ادمین CRUD با ویرایشگر متن امن (Sanitize HTML).

## فاز ۵ — انبارداری و انبارگردانی ⬜

- انبار(ها)، **دفتر حرکات کالا** (ورود، خروج، فروش، مرجوعی، تعدیل، انتقال) — موجودی همیشه از جمع حرکات محاسبه می‌شود.
- رزرو موجودی هنگام پرداخت و آزادسازی پس از انقضا/لغو؛ جلوگیری از فروش بیش از موجودی (همزمانی).
- **انبارگردانی:** ایجاد دورهٔ شمارش، ثبت مقدار شمارش‌شده، گزارش مغایرت، تأیید و ثبت سند تعدیل.
- هشدار حداقل موجودی، تأمین‌کنندگان، رسید خرید.
- بهای تمام‌شده به روش میانگین موزون.

## فاز ۶ — ویترین فروشگاه ⬜

- صفحهٔ اصلی: **پرفروش‌ترین‌ها**، **تخفیف‌های ویژه** (با بازهٔ زمانی و شمارش معکوس)، جدیدترین‌ها، دسته‌های محبوب.
- لیست محصولات با **فیلتر** (دسته، برند، بازهٔ قیمت، ویژگی‌ها، فقط موجود، فقط تخفیف‌دار)
  و **مرتب‌سازی** (ارزان‌ترین، گران‌ترین، جدیدترین/تاریخ عرضه، پرفروش‌ترین، محبوب‌ترین/امتیاز، پربازدیدترین، بیشترین تخفیف).
- جستجو: Full-Text Search در SQL Server + پیشنهاد هنگام تایپ؛ صفحه‌بندی سمت سرور.
- صفحهٔ محصول: گالری تصویر و ویدئو، مشخصات، محصولات مشابه.
- **نظرات:** امتیاز ۱ تا ۵، متن، نشان «خریدار این محصول»، تأیید ادمین، رأی مفید بودن، گزارش تخلف، ضد اسپم.
- علاقه‌مندی‌ها و مقایسهٔ محصول.

## فاز ۷ — سبد خرید، تسویه و سفارش ⬜

- سبد برای مهمان (کوکی) و ادغام پس از ورود.
- **قیمت همیشه سمت سرور محاسبه می‌شود** (هرگز از فرم پذیرفته نمی‌شود).
- آدرس، روش ارسال و هزینهٔ آن، کد تخفیف، مالیات (مثلاً ارزش افزوده).
- چرخهٔ عمر سفارش (Pending → Paid → Shipped → Completed / Canceled / Refunded) با تاریخچه.
- همهٔ اکشن‌ها با چک مالکیت (درس IDOR از BulkyWeb). ایمیل اطلاع‌رسانی.

## فاز ۸ — درگاه‌های پرداخت ⬜

- `IPaymentGateway` (الگوی Strategy) — افزودن درگاه جدید بدون تغییر کد تسویه.
- بین‌المللی: **Stripe**، **PayPal**، **Paddle**.
- ایرانی: **زرین‌پال**، **سداد (بانک ملی)**، **به‌پرداخت ملت**.
- تأیید پرداخت فقط سمت سرور (Verify / Webhook با بررسی امضا)، Idempotency، ثبت همهٔ تراکنش‌ها، بازپرداخت.
- فعال/غیرفعال‌سازی هر درگاه و ارز آن از پنل ادمین.

> ⚠️ نکات تصمیم‌گیری:
> - **Paddle** فقط محصولات دیجیتال/نرم‌افزاری را می‌پذیرد، نه کالای فیزیکی.
> - Stripe و PayPal برای حساب‌های ایرانی در دسترس نیستند و درگاه‌های ایرانی فقط ریال می‌پذیرند؛
>   بنابراین هر استقرار (Deployment) مجموعهٔ درگاه و ارز خود را دارد.

## فاز ۹ — حسابداری ⬜

- دفتر کل دوطرفه ساده: سرفصل حساب‌ها، سند حسابداری و اقلام آن (بدهکار/بستانکار همیشه برابر).
- **ثبت خودکار سند** از فروش، پرداخت، بازپرداخت، خرید از تأمین‌کننده و تعدیل انبار.
- ثبت هزینه‌ها، صندوق/بانک.
- گزارش‌ها: سود و زیان، فروش روزانه/ماهانه، مالیات، ارزش موجودی، دفتر معین. خروجی Excel/PDF.
- اسناد قطعی غیرقابل ویرایش (فقط سند اصلاحی).

## فاز ۱۰ — پنل مدیریت و گزارش‌ها ⬜

- داشبورد (فروش، سفارش‌های جدید، موجودی کم، نظرات در انتظار تأیید).
- مدیریت کاربران و نقش‌ها، تنظیمات فروشگاه، صفحات محتوایی (درباره ما، قوانین).
- **لاگ ممیزی** (چه کسی، چه زمانی، چه تغییری).
- اعلان‌ها (ایمیل؛ پیامک به‌صورت اختیاری).

## فاز ۱۱ — کارایی، SEO و سخت‌سازی امنیتی ⬜

- Output caching، Response compression، کش داده‌های پرتکرار (پرفروش‌ها، منو)، کوئری‌های `AsNoTracking` و Projection.
- Bundle/minify، تصاویر بهینه، CDN اختیاری. هدف: **Lighthouse ≥ 90** در موبایل.
- SEO: آدرس‌های Slug، `sitemap.xml`، داده‌های ساختاریافته (Schema.org Product/Review)، Open Graph.
- دسترس‌پذیری (WCAG AA).
- چک‌لیست OWASP Top 10، تست نفوذ پایه (OWASP ZAP)، بازبینی کد امنیتی.

## فاز ۱۲ — مستندات، استقرار و انتشار ⬜

- مستندات به فارسی و انگلیسی.

## سؤالات باز (نیازمند تصمیم مالک پروژه)

1. نقش **Seller** (چندفروشنده) برای فروشگاه کوچک لازم است یا با نقش‌های کارمندی (Manager/Warehouse/Accountant) جایگزین شود؟
2. ارزهای مورد نیاز هر استقرار (ریال/تومان، دلار، یورو، درام ارمنستان و ...)؟
3. پایگاه داده فقط SQL Server، یا PostgreSQL هم برای هاست ارزان‌تر لینوکسی پشتیبانی شود؟
4. پیامک (OTP و اطلاع‌رسانی) لازم است؟ کدام سرویس‌دهنده؟
