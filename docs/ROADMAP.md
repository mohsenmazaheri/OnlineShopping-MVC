# نقشهٔ راه و فازبندی پروژهٔ OnlineShopping-MVC

> هدف: فروشگاه اینترنتی **تک‌فروشگاهی برای کسب‌وکارهای کوچک** (تعداد مشتری کم تا متوسط)، سریع، زیبا، امن،
> چندزبانه، **PWA و موبایل‌محور**، با انبارداری و حسابداری، **Cross-Platform** (لینوکس و ویندوز).
>
> هر فاز یک خروجی قابل اجرا و قابل تست دارد. فاز بعدی فقط وقتی شروع می‌شود که «معیار پایان» فاز قبل برآورده شده باشد.
> وضعیت‌ها: ✅ انجام شد · 🔄 در حال انجام · ⬜ شروع نشده

## تصمیم‌های معماری (ثبت‌شده)

| موضوع | تصمیم |
|---|---|
| ساختار مخزن | **Monorepo**: بک‌اند ‎.NET و فرانت‌اند Next.js در یک مخزن. |
| فرانت‌اند | **Next.js (React + TypeScript)** برای ویترین فروشگاه و پنل مدیریت؛ SSR/ISR برای سرعت و SEO؛ **PWA** (نصب‌پذیر، Service Worker، کش آفلاین پوسته)؛ طراحی Mobile-first. |
| بک‌اند | **ASP.NET Core 10 Web API** (پروژهٔ MVC فعلی به API تبدیل می‌شود؛ Viewهای Razor در فاز ۱ حذف می‌شوند). |
| احراز هویت بین Next.js و API | الگوی BFF: کوکی `HttpOnly`/`Secure`/`SameSite`، بدون نگهداری توکن در `localStorage`. |
| پایگاه داده | **Code-first با Migration جداگانه برای هر پایگاه داده.** هدف اول **PostgreSQL** (✅ نصب‌شده روی سیستم توسعه)، سپس SQL Server و MySQL. نام جدول/ستون‌ها `snake_case`. |
| انتخاب پایگاه داده | تنظیم `Database:Provider` (`PostgreSql` / `SqlServer` / `MySql`) + یک اسمبلی Migration برای هر Provider. |
| Cross-Platform | فقط APIهای چندسکویی؛ Docker Compose (postgres + api + web)؛ راهنمای اجرا روی لینوکس (systemd + Nginx) و ویندوز (IIS / Windows Service). |
| نقش‌ها | دو حالت: **فروشگاه یک‌نفره** (مالک فقط نقش `Admin` دارد و همه‌چیز را می‌بیند) و **فروشگاه با تقسیم وظایف** (`Manager`، `Warehouse`، `Accountant`). مجوزها Permission-based (Policy) هستند و نقش‌ها مجموعه‌ای از مجوزها. نقش Seller (چندفروشنده) حذف شد. |
| ارز و درگاه | قابل تنظیم توسط **مدیر سیستم** برای هر استقرار (پایین‌تر). |
| پیامک | **اختیاری.** پیش‌فرض خاموش؛ همهٔ امکانات بدون پیامک کار می‌کنند. با روشن کردن، OTP و اطلاع‌رسانی پیامکی فعال می‌شود. در نسخهٔ ایران عملاً روشن است (پایین‌تر). |
| مدل استقرار | **نصب جدا برای هر فروشگاه** (Single-tenant): هر فروشگاه یک کانتینر و یک دیتابیس جدا. بدون `tenant_id` در مدل داده. همهٔ فروشگاه‌ها از یک Docker image نسخه‌دار به‌روز می‌شوند. |
| کانال فروش | فقط **فروش آنلاین کالای فیزیکی به مشتری نهایی (B2C)**. بدون POS، بدون محصول دیجیتال، بدون فروش عمده. |
| قیمت چندارزی | **ارز پایه + نرخ تبدیل:** قیمت فقط در ارز پایه وارد می‌شود؛ بقیهٔ ارزها با نرخ تبدیلِ مدیر و قاعدهٔ گرد کردن هر ارز محاسبه می‌شوند؛ قیمت دستی برای محصولات خاص مجاز است. مبلغ سفارش در ارزی که مشتری پرداخت کرده ثبت و قفل می‌شود. |
| مالیات | **فقط نرخ ساده:** یک نرخ مالیات برای هر فروشگاه + انتخاب «قیمت‌ها با مالیات/بدون مالیات» + فاکتور PDF با شمارهٔ پیوسته. انطباق قانونی (سامانهٔ مودیان، VAT اتحادیهٔ اروپا، e-HDM) با خود فروشنده و حسابدارش است و در راهنما ذکر می‌شود. |
| بازار نسخهٔ ۱ | **همهٔ بازارها هم‌زمان** (ایران، ارمنستان، اروپا) با همهٔ زبان‌ها و درگاه‌ها. |
| برند فروشگاه | **چند قالب آماده:** نام، لوگو، رنگ اصلی، فونت و بنرها از پنل + چند قالب چیدمان برای صفحهٔ اصلی و لیست محصولات. |
| ترجمهٔ محتوا | **فقط دستی:** بدون سرویس خارجی؛ هر فروشگاه فقط زبان‌هایی را فعال می‌کند که ترجمه کرده؛ محتوای ترجمه‌نشده به زبان پیش‌فرض برمی‌گردد (و در آن زبان `noindex` است). |
| موتور جستجو | پشت `IProductSearch`، با تنظیم `Search:Provider`: **PostgreSQL پیش‌فرض** (Full-Text + `pg_trgm`)، **OpenSearch** یا **Elasticsearch** اختیاری روی سرور خود فروشگاه. PostgreSQL همیشه منبع حقیقت است؛ ایندکس با Outbox همگام می‌شود و اگر موتور از دسترس خارج شود، جستجو به PostgreSQL برمی‌گردد (فاز ۶). |
| SEO و بازاریابی | طراحی کامل در **[SEO-MARKETING.md](SEO-MARKETING.md)**: SSR/ISR، آدرس `/{locale}/p/{number}/{slug}`، hreflang، Schema.org، Sitemap، Redirect، بلاگ، فیدهای Google/Meta/ترب/ایمالز، ابزارهای سنجش فقط با رضایت کاربر. |

### ارز و درگاه پرداخت (تنظیمات مدیر سیستم)

- مدیر سیستم ارزهای فعال، ارز پایه، نرخ تبدیل (دستی) و درگاه‌های فعال را انتخاب می‌کند؛ هر درگاه فقط ارزهای پشتیبانی‌شدهٔ خود را می‌پذیرد.
- پیش‌تنظیم‌های پیشنهادی (قابل تغییر):

| منطقه | ارزها | درگاه‌ها | ورود |
|---|---|---|---|
| اروپا | EUR، USD | Stripe، PayPal | ایمیل، Google، Facebook، Microsoft |
| ارمنستان | AMD، EUR، USD | Stripe، PayPal | ایمیل، Google، Facebook، Microsoft |
| ایران | فقط IRR | زرین‌پال، سداد، به‌پرداخت ملت | **پیامک (OTP)** + ایمیل؛ ورود خارجی خاموش |

- مبلغ همیشه همراه کد ارز ذخیره می‌شود (Value object `Money`)؛ تعداد رقم اعشار از ارز می‌آید (ریال و درام بدون اعشار).
- **Paddle از فهرست درگاه‌ها خارج شد:** فقط محصولات دیجیتال را می‌پذیرد و برنامه فقط کالای فیزیکی می‌فروشد. اگر روزی محصول دیجیتال اضافه شود، دوباره بررسی می‌شود.

### نسخهٔ ایران

- میزبانی روی **سرور داخل ایران** (درگاه‌های شاپرکی معمولاً IP ایران می‌خواهند).
- ورود اصلی با **کد پیامکی** + ایمیل؛ Google/Facebook/Microsoft خاموش.
- **هیچ وابستگی خارجی در زمان اجرا:** فونت‌ها، آیکون‌ها، اسکریپت‌ها و تصاویر روی سرور خود فروشگاه (این قاعده برای همهٔ نسخه‌ها اجرا می‌شود؛ برای GDPR در آلمان هم لازم است).
- Docker Hub و برخی مخازن بسته (NuGet/npm) از ایران محدودند: imageها خارج از ایران در CI ساخته و در یک رجیستری در دسترس از ایران منتشر می‌شوند.
- تاریخ شمسی، ارقام فارسی و یکسان‌سازی «ی/ي» و «ک/ك».

## فاز ۱ — Monorepo، معماری و زیرساخت 🔄

**خروجی:** اسکلت کامل قابل اجرا روی لینوکس و ویندوز.

```
apps/web/                                   Next.js 16 (TypeScript, App Router, Cache Components, PWA)
src/OnlineShopping.Domain/                  موجودیت‌ها (بدون وابستگی)
src/OnlineShopping.Application/             Use caseها، Result<T>، IApplicationDbContext، StoreOptions
src/OnlineShopping.Infrastructure/          EF Core/PostgreSQL، Identity، Data Protection، Seeder
src/OnlineShopping.Infrastructure.Migrations.PostgreSql/
src/OnlineShopping.Api/                     ASP.NET Core Web API
tests/OnlineShopping.UnitTests, tests/OnlineShopping.IntegrationTests (PostgreSQL واقعی)
deploy/                                     Dockerfileها، docker-compose، نمونهٔ nginx
```

انجام شد ✅
- Node.js 26 LTS روی سیستم توسعه؛ تفکیک لایه‌ها؛ Central Package Management؛ Analyzerها با «هشدار = خطا».
- API: endpointهای `/api/v1/store` و `/api/v1/catalog/categories`، OpenAPI (تولید در زمان build + کلاینت تایپ‌شدهٔ TypeScript)، `ProblemDetails` با کد خطا، `Result<T>`، Serilog، `/health/live` و `/health/ready`، Options validation در Startup.
- امنیت API: هدرهای امنیتی، HSTS، Rate limiting، تنظیم امن Forwarded headers، کلیدهای Data Protection در پایگاه داده، OpenAPI فقط در Development.
- Next.js: مسیرهای `/{locale}` با RTL/LTR، canonical/hreflang، robots/sitemap/manifest، آیکون PWA، Service Worker (صفحات همیشه از شبکه)، صفحهٔ آفلاین، CSP و هدرهای امنیتی، endpoint بازسازی کش با رمز مشترک.
- **یک image برای همهٔ فروشگاه‌ها:** تنظیمات فروشگاه فقط در API است و Next.js آن‌ها را در زمان درخواست می‌خواند؛ build به API نیاز ندارد (با یک build، دو پیکربندی متفاوت آزموده شد).
- Docker (API، web، PostgreSQL)، `.env.example`، نمونهٔ nginx، workflow CI (build، تست با PostgreSQL، اسکن آسیب‌پذیری، بررسی هم‌خوانی Migration و OpenAPI، ساخت image).
- تست‌ها: ۶۹ واحد + ۱۰ یکپارچه‌سازی (.NET) و ۵۴ تست Next.js.

باقی‌مانده ⬜
- اجرای واقعی `docker compose up` روی لینوکس و ویندوز (Docker روی سیستم توسعه نصب نیست) و اولین اجرای سبز CI در GitHub.
- ثبت Service Worker در یک مرورگر واقعی (مرورگر داخلی محیط توسعه اجازهٔ Service Worker نمی‌دهد).
- Lighthouse CI و Prettier؛ OpenTelemetry؛ رجیستری image قابل دسترس از ایران.
- به فاز مصرف‌کننده منتقل شد: FluentValidation و Antiforgery (فاز ۲، اولین فرم‌ها)، صف کارهای پس‌زمینه (فاز ۵/۷).

**معیار پایان:** `docker compose up` روی لینوکس و ویندوز صفحهٔ اصلی Next.js را با داده از API نشان دهد؛ CI سبز.

## فاز ۲ — هویت، نقش‌ها و حساب کاربری 🔄

**تصمیم‌های ثبت‌شده**

| موضوع | تصمیم |
|---|---|
| شناسهٔ حساب | **ایمیل یا موبایل** (حداقل یکی، هر دو یکتا). موبایل به قالب بین‌المللی E.164 یکسان‌سازی می‌شود (منطقهٔ پیش‌فرض از تنظیمات فروشگاه). مدیر سیستم روش‌های ورود را روشن/خاموش می‌کند. |
| پیامک | رابط `ISmsSender` با **کاوه‌نگار، SMS.ir و Twilio**؛ پیش‌فرض **خاموش** (`NullSmsSender`). |
| مجوزها | **ثابت در کد:** هر نقش مجموعهٔ مشخصی از مجوزها؛ هر کارمند می‌تواند چند نقش داشته باشد؛ `Admin` همهٔ مجوزها را دارد. |
| ورود دومرحله‌ای | **اختیاری برای همه**؛ تنظیم `Security:RequireStaffTwoFactor` (پیش‌فرض خاموش) برای اجباری کردن در کارمندان. |
| نشست کاربر | کوکی Identity صادرشده توسط API (`HttpOnly`، `SameSite=Lax`، `Secure` در HTTPS) که از طریق proxy هم‌مبدأ Next.js به مرورگر می‌رسد؛ هیچ توکنی در JavaScript یا `localStorage` نیست. |
| CSRF | کوکی `SameSite=Lax` + فقط بدنهٔ JSON برای درخواست‌های تغییردهنده + بررسی هدر `Origin` در API (جایگزین Antiforgery کلاسیک که برای API مناسب نیست). |
| ایمیل | SMTP (MailKit) که با هر سرویس‌دهنده کار می‌کند؛ در Development ایمیل‌ها به‌صورت فایل `.eml` در پوشهٔ محلی ذخیره می‌شوند. |

**زیرمرحله‌ها**

- **۲الف ✅:** کاربر با ایمیل یا موبایل (یکتا، موبایل به E.164 و پذیرش ارقام فارسی/عربی)، مدل مجوزهای ثابت، کوکی ورود (`HttpOnly`/`SameSite=Lax`)، ثبت‌نام/ورود/خروج/«من کیستم»، تأیید ایمیل، فراموشی و بازنشانی رمز (پیوند یک‌بارمصرف ۲ ساعته؛ پایان سایر نشست‌ها)، قفل حساب پس از ۵ تلاش، سیاست رمز (حداقل ۸ کاراکتر + عدد؛ در ۱۴۰۵-۰۸-۱۸ از ۱۲ به ۸ کاهش یافت، همراه دکمهٔ نمایش/پنهان کردن رمز در همهٔ فرم‌ها)، FluentValidation با کدهای خطای ترجمه‌پذیر، بررسی `Origin`، محدودیت سخت‌تر نرخ برای endpointهای ورود، ایمیل چندزبانه (SMTP/فایل `.eml`)؛ صفحات ورود، ثبت‌نام، فراموشی/بازنشانی رمز، تأیید ایمیل و حساب کاربری در Next.js با هدایت امن پس از ورود؛ رفع قواعد `robots.txt` برای مسیرهای دارای پیشوند زبان.
- **۲ب ✅:** پیامک با کاوه‌نگار (Verify Lookup)، SMS.ir (Verify) و Twilio + حالت `Pickup` برای توسعه؛ **ورود و ثبت‌نام یکپارچه با کد پیامکی** (شمارهٔ جدید = ساخت حساب تأییدشده، بدون افشای ثبت‌شده بودن شماره)؛ حساب‌های موبایلی بدون رمز؛ ثبت‌نام با رمز فقط با ایمیل؛ افزودن موبایل تأییدشده به حساب ایمیلی؛ کد ۶ رقمی تصادفی امن، ذخیرهٔ فقط هش نمک‌دار، اعتبار ۳ دقیقه، ۵ تلاش، فاصلهٔ ۶۰ ثانیه، حداکثر ۵ کد در ساعت برای هر شماره (+ محدودیت IP)؛ قفل حساب با کد دور زده نمی‌شود؛ پرشدن خودکار کد در اندروید (WebOTP)؛ پذیرش ارقام فارسی/عربی؛ جلوگیری از ثبت کلید API در لاگ.
- **۲ج ✅:** ورود و ثبت‌نام با Google، Facebook و Microsoft (هر سرویس فقط وقتی کلیدش تنظیم شده نمایش داده می‌شود؛ در نسخهٔ ایران خالی)؛ اتصال خودکار به حساب موجود **فقط با ایمیل تأییدشده توسط Google** (جلوگیری از تصاحب حساب)، در غیر این صورت ورود و اتصال از صفحهٔ حساب؛ اتصال/جداسازی سرویس‌ها با منع حذف آخرین روش ورود؛ آدرس بازگشت OAuth از آدرس عمومی فروشگاه (PKCE، کوکی correlation با `SameSite=Lax`)؛ لغو یا پاسخ جعلی به صفحهٔ ورود با پیام ترجمه‌شده برمی‌گردد؛ دکمه‌های متنی بدون لوگو. ⚠️ ورود واقعی با هر سرویس هنوز با اپ واقعی آزموده نشده است.
- **۲د ✅:** ورود دومرحله‌ای اختیاری برای همه با برنامهٔ Authenticator (TOTP، کد QR در خود مرورگر ساخته می‌شود و کلید به هیچ سرویس بیرونی نمی‌رود)؛ ۱۰ کد بازیابی یک‌بارمصرف (نمایش فقط یک بار، دانلود، تجدید با کد)؛ «این دستگاه را به خاطر بسپار» و فراموش کردن دستگاه؛ مرحلهٔ دوم بعد از رمز، کد پیامکی و ورود با Google/Facebook/Microsoft؛ خاموش کردن فقط با کد فعلی؛ تنظیم `Security:RequireStaffTwoFactor` (پیش‌فرض خاموش) که دسترسی‌های کارکنان را به ورود دومرحله‌ای مشروط می‌کند.
- **۲هـ ✅:** صفحهٔ حساب با سه بخش (حساب، آدرس‌ها، حریم خصوصی)؛ ویرایش نام و زبان ایمیل/پیامک؛ تغییر رمز با رمز فعلی (خروج از دستگاه‌های دیگر)؛ **دفترچهٔ آدرس** (حداکثر ۲۰، یک آدرس پیش‌فرض، شماره به E.164 بر اساس کشور آدرس، اعتبارسنجی کد پستی ایران/ارمنستان/آلمان و…، پذیرش ارقام فارسی، حذف واقعی نه نرم، فقط کشورهای `Store:ShippingCountries`، بررسی مالکیت در خود کوئری)؛ **دانلود همهٔ اطلاعات شخصی** به‌صورت فایل JSON؛ **حذف حساب**: آدرس‌ها، سبد و کدهای پیامکی واقعاً حذف می‌شوند، ردیف کاربر بدون هیچ اطلاعات شخصی می‌ماند تا سفارش‌ها (سوابق مالی) سالم بمانند، همهٔ نشست‌ها باطل می‌شوند و ایمیل/شماره آزاد می‌شود؛ تأیید با رمز، یا برای حساب‌های بدون رمز ورود در ۱۰ دقیقهٔ اخیر (`Auth:ReauthenticationMinutes`)؛ کارمندان خودشان را حذف نمی‌کنند؛ تنظیم `Store:GuestCheckout` (پیش‌فرض روشن) در اطلاعات فروشگاه. رفع یک اشکال ۲د: بررسی دوره‌ای security stamp ادعای `amr=mfa` و زمان ورود را حذف می‌کرد. ⚠️ تغییر ایمیل هنوز نیست. ⚠️ وقتی سفارش‌ها آدرس و مشخصات تماس بگیرند (فاز ۵)، `PersonalDataService.DeleteAsync` باید آن‌ها را هم پاک کند.
- **۲و:** مدیریت کارمندان در پنل: دعوت، تعیین نقش، غیرفعال‌سازی.

## فاز ۳ — چندزبانگی، تم، سیستم طراحی و PWA ⬜

- زبان‌ها: **fa، en، hy، de، ar**؛ افزودن زبان جدید = یک فایل پیام در Next.js + یک ردیف در تنظیمات.
- متن رابط کاربری با `next-intl`؛ محتوای پایگاه داده با جدول‌های ترجمه و Fallback به زبان پیش‌فرض؛ مسیر `/{locale}/…` و `hreflang`.
- RTL برای fa/ar، LTR برای بقیه؛ تاریخ شمسی برای fa؛ قالب عدد و ارز بر اساس زبان.
- **تم روشن و تیره** (پیش‌فرض بر اساس سیستم، قابل تغییر و ذخیره، بدون چشمک هنگام بارگذاری).
- سیستم طراحی مستقل (Tailwind CSS + کامپوننت‌های خودمان)، Skeleton loading، انیمیشن‌های سبک.
- **قالب‌ها و برند:** توکن‌های طراحی (رنگ، فونت، گردی گوشه‌ها) از پنل؛ لوگو و بنرها؛ چند قالب چیدمان آماده برای صفحهٔ اصلی و لیست محصولات (انتخاب از پنل، بدون نیاز به build دوباره).
- همهٔ فونت‌ها و آیکون‌ها self-hosted (Vazirmatn برای فارسی/عربی، فونت OFL با پشتیبانی ارمنی برای hy).
- مسیرهای همیشه با پیشوند زبان، `hreflang` فقط برای زبان‌های ترجمه‌شده + `x-default`، قالب عنوان/توضیحات برای هر زبان ([SEO-MARKETING](SEO-MARKETING.md) بندهای ۲ تا ۴).
- **Mobile-first**: نوار پایین موبایل، منوی کشویی، لمس‌پذیری؛ PWA نصب‌پذیر با صفحهٔ آفلاین.

## فاز ۴ — کاتالوگ محصولات ⬜

- دسته‌بندی درختی، برند، ویژگی‌ها و مشخصات فنی قابل فیلتر، تنوع محصول (رنگ/سایز).
- **مدل دادهٔ ویژگی‌ها (پایهٔ جستجو، فیلتر و مقایسه):**
  - هر دسته یک **قالب ویژگی** دارد (گروه‌ها مثل «صفحه‌نمایش» و «حافظه»، ترتیب نمایش، واحد).
  - نوع هر ویژگی: متنی، عددی با واحد، بله/خیر، یا انتخاب از فهرست مقادیر ترجمه‌شده. هر ویژگی پرچم «قابل فیلتر»، «قابل مقایسه» و «در خلاصهٔ محصول» دارد.
  - مقادیر در جدول جداگانهٔ `product_attribute_values` ذخیره می‌شوند: مقدار عددی در ستون عددی و انتخاب‌ها با شناسهٔ گزینه. ایندکس‌ها برای فیلتر و شمارش (facet) سریع طراحی می‌شوند؛ متن آزاد داخل JSON فیلترپذیر نیست.
  - ویژگی‌های سطح تنوع (رنگ، سایز) از ویژگی‌های سطح محصول جدا هستند.
- فیلدهای جستجو در مدل: نام‌ها و برچسب‌های هر زبان، SKU، GTIN/بارکد، `public_number`. **مترادف‌ها** هم از پنل مدیریت می‌شوند (جدول `search_synonyms`، برای هر زبان؛ مثلاً «گوشی = موبایل = تلفن همراه»).
- **چند تصویر و ویدئو برای هر محصول** پشت `IFileStorage` (دیسک محلی / S3-compatible)؛ امنیت آپلود (Magic bytes، حجم، بازسازی تصویر)؛ WebP/AVIF و اندازه‌های مختلف.
- پنل مدیریت محصولات در Next.js؛ ترجمهٔ دستی هر فیلد برای زبان‌های فعال با نمایش «ترجمه‌نشده».
- **ورود و خروج گروهی محصولات و موجودی با CSV/Excel** (برای راه‌اندازی سریع فروشگاه‌هایی که از جای دیگر می‌آیند).
- فیلدهای SEO در مدل ([SEO-MARKETING](SEO-MARKETING.md) «اثر روی مدل داده»): `public_number`، GTIN/MPN، وزن، slug و متای هر زبان، متن جایگزین تصویر؛ جدول `redirects` با 301 خودکار هنگام تغییر slug؛ پیش‌نمایش نتیجهٔ گوگل و هشدارهای SEO در پنل.
- ویدئو: MP4 با محدودیت حجم، پخش با Range request؛ بدون تبدیل فرمت در نسخهٔ ۱. ذخیره‌سازی پیش‌فرض دیسک محلی؛ S3-compatible اختیاری (در ایران مثلاً فضای ابری داخلی).

## فاز ۵ — انبارداری و انبارگردانی ⬜

- انبار(ها)، دفتر حرکات کالا (ورود، خروج، فروش، مرجوعی، تعدیل، انتقال)؛ موجودی = جمع حرکات.
- رزرو موجودی هنگام پرداخت؛ جلوگیری از فروش بیش از موجودی.
- **انبارگردانی:** دورهٔ شمارش، ثبت شمارش، گزارش مغایرت، سند تعدیل.
- هشدار حداقل موجودی، تأمین‌کنندگان، رسید خرید، بهای تمام‌شده (میانگین موزون).

## فاز ۶ — ویترین فروشگاه ⬜

- صفحهٔ اصلی: **پرفروش‌ترین‌ها**، **تخفیف‌های ویژه** با شمارش معکوس، جدیدترین‌ها.
- **فیلتر** (دسته، برند، قیمت، ویژگی، موجود، تخفیف‌دار) و **مرتب‌سازی** (مرتبط‌ترین، قیمت، تاریخ عرضه، پرفروش، محبوب/امتیاز، پربازدید، بیشترین تخفیف).
- **فیلترهای پویا (facet):** گزینه‌ها از ویژگی‌های قابل فیلتر همان دسته یا همان نتیجهٔ جستجو ساخته می‌شوند، با تعداد نتیجه کنار هر گزینه (مثل «سامسونگ (۱۲)»). گزینه‌های بی‌نتیجه غیرفعال می‌شوند. بازهٔ عددی (قیمت به ارز نمایش‌داده‌شده، حافظه، اندازه) با کمینه/بیشینهٔ واقعی. فیلترهای انتخاب‌شده به‌صورت برچسب قابل حذف نمایش داده می‌شوند. همه چیز بدون JavaScript هم کار می‌کند (فرم GET).
- **جستجوی پیشرفته:**
  - Full-Text در PostgreSQL: پیکربندی `simple`، به‌علاوهٔ `pg_trgm` برای تحمل غلط تایپی (PostgreSQL برای فارسی، عربی و ارمنی ریشه‌یاب ندارد).
  - یکسان‌سازی پیش از ایندکس و پرس‌وجو: «ي/ی» و «ك/ک»، ارقام فارسی و عربی، نیم‌فاصله، اعراب، حروف کوچک لاتین.
  - **رتبه‌بندی وزن‌دار:** تطابق در نام مهم‌تر از برند و دسته، و آن‌ها مهم‌تر از توضیحات. کالای موجود و پرفروش کمی بالاتر می‌آید.
  - **چندزبانه:** جستجو در ترجمهٔ زبان فعلی، با بازگشت به زبان پیش‌فرض. نام‌های لاتین (مثل «Galaxy») در همهٔ زبان‌ها پیدا می‌شوند.
  - **کد کالا:** تطابق دقیق SKU، GTIN/بارکد و شمارهٔ عمومی محصول، که مستقیم به صفحهٔ محصول می‌رود.
  - **مترادف‌ها** از پنل.
  - **صفحه‌کلید اشتباه:** «lfhdg» به‌صورت «مبایل» هم جستجو می‌شود و برعکس (نگاشت صفحه‌کلید فارسی/انگلیسی، و برای ارمنی/انگلیسی).
  - جستجو با فیلترها و مرتب‌سازی ترکیب می‌شود.
- **پیشنهاد هنگام تایپ:** محصولات با تصویر و قیمت، دسته‌ها و برندهای مرتبط، جستجوهای پرتکرار. پاسخ سریع (هدف زیر ۱۰۰ میلی‌ثانیه سمت سرور)، با debounce و لغو درخواست قبلی.
- **نتیجهٔ صفر:** پیشنهاد «منظورتان … بود؟» (نزدیک‌ترین عبارت با `pg_trgm`)، حذف خودکار سخت‌گیرانه‌ترین فیلتر، و نمایش پرفروش‌ها به‌جای صفحهٔ خالی. عبارت‌های بی‌نتیجه برای گزارش ثبت می‌شوند.
- **موتور جستجوی قابل تعویض:** همهٔ منطق پشت `IProductSearch` است و ویترین فقط با همین رابط کار می‌کند. انتخاب با تنظیم `Search:Provider`:
  - `Postgres` (**پیش‌فرض**): بدون سرویس اضافه، کافی برای فروشگاه کوچک (تا چند هزار محصول).
  - `OpenSearch` (گزینهٔ اصلی برای فروشگاه بزرگ): مجوز Apache 2.0، تحلیلگرهای آمادهٔ `persian`، `arabic` و `armenian`، aggregation برای facet، مترادف و تحمل غلط تایپی در خود موتور.
  - `Elasticsearch`: پیاده‌سازی جداگانه (کتابخانهٔ .NET آن از نسخهٔ ۸ با OpenSearch فرق دارد)، برای فروشگاهی که خودش Elasticsearch دارد یا آن را می‌خواهد. مسئولیت مجوز (Elastic License / SSPL / AGPL) با مدیر سیستم همان نصب است.
  - Meilisearch در نسخهٔ ۱ نیست؛ اگر لازم شد، بعداً پیاده‌سازی دیگری از همین رابط است.
  - **منبع حقیقت همیشه PostgreSQL است** و موتور جستجو فقط کپی قابل بازسازی نگه می‌دارد:
    - ایندکس‌کردن قابل اطمینان با **الگوی Outbox**: تغییر محصول، قیمت، موجودی، ترجمه یا مترادف در همان تراکنش یک رکورد outbox می‌نویسد و یک سرویس پس‌زمینه آن را با تلاش دوباره به موتور می‌فرستد.
    - دستور **بازسازی کامل ایندکس** (پنل مدیر سیستم و خط فرمان)، با ایندکس جدید و جابه‌جایی alias، بدون قطعی.
    - یک ایندکس برای هر زبان فعال، با تحلیلگر همان زبان.
    - **بررسی سلامت**: اگر موتور در دسترس نباشد یا ایندکس عقب باشد، جستجو خودکار به PostgreSQL برمی‌گردد و هشدار ثبت می‌شود؛ سایت نمی‌خوابد.
    - قیمت و موجودی نمایش‌داده‌شده همیشه از PostgreSQL خوانده می‌شود، نه از ایندکس.
  - تست‌ها: یک مجموعه تست قراردادی مشترک (همان سناریوها برای هر سه موتور)؛ تست یکپارچهٔ OpenSearch/Elasticsearch با Testcontainers در CI.
  - استقرار: پروفایل اختیاری `search` در `docker-compose` که OpenSearch را فقط برای نصب‌هایی که می‌خواهند بالا می‌آورد (حداقل حدود ۲ گیگابایت RAM اضافه). در ایران، image موتور هم باید از رجیستری قابل دسترس از ایران بیاید (Elastic دانلود از ایران را مسدود می‌کند).
- **مقایسهٔ محصولات:**
  - افزودن از کارت محصول و صفحهٔ محصول، تا ۴ محصول (۲ تا روی موبایل کنار هم، بقیه با اسکرول افقی).
  - فقط محصولات **یک دسته** (یا دسته‌های با قالب ویژگی سازگار) مقایسه می‌شوند؛ افزودن از دستهٔ دیگر هشدار می‌دهد.
  - نوار شناور «مقایسه (۳)» در پایین صفحه. فهرست برای مهمان در مرورگر و برای کاربر واردشده در حساب ذخیره می‌شود و پس از ورود ادغام می‌شود.
  - جدول مقایسه: تصویر، نام، قیمت و موجودی فعلی (از سرور، نه از کش مرورگر)، امتیاز، سپس ویژگی‌های «قابل مقایسه» به ترتیب گروه‌های قالب، با واحد و ترجمه.
  - گزینهٔ **«فقط تفاوت‌ها»**، و برجسته کردن بهترین مقدار در ویژگی‌های عددی که جهت بهتر دارند (مثلاً حافظهٔ بیشتر، وزن کمتر؛ جهت در قالب ویژگی تعریف می‌شود).
  - دکمهٔ افزودن به سبد از همان جدول؛ آدرس قابل اشتراک (`/{locale}/compare?ids=…`).
  - مقادیر ترجمه‌نشده به زبان پیش‌فرض برمی‌گردند؛ مقدار خالی با «—» نمایش داده می‌شود.
- صفحهٔ محصول با گالری تصویر/ویدئو؛ **نظرات** (امتیاز، خریدار تأییدشده، تأیید ادمین، ضد اسپم)؛ علاقه‌مندی.
- SEO ویترین ([SEO-MARKETING](SEO-MARKETING.md) بندهای ۵، ۷، ۸): JSON-LD محصول/دسته/بردکرامب، canonical و `noindex` برای فیلترها، **صفحات فرود** برای ترکیب‌های پرجستجو، صفحه‌بندی با لینک واقعی، رفتار درست ناموجود/حذف‌شده، تصویر اشتراک‌گذاری خودکار، Sitemap تصویر و ویدئو.
- **بلاگ و صفحات محتوایی چندزبانه** (بند ۹).

## فاز ۷ — سبد خرید، تسویه و سفارش ⬜

- سبد مهمان و ادغام پس از ورود؛ قیمت فقط سمت سرور؛ آدرس، کد تخفیف.
- **مالیات ساده:** یک نرخ برای فروشگاه، قیمت با/بدون مالیات؛ **فاکتور PDF** چندزبانه با شمارهٔ پیوسته.
- **ارسال:** روش‌های قابل تعریف از پنل (هزینهٔ ثابت، بر اساس وزن/منطقه، رایگان بالای مبلغ مشخص، تحویل حضوری)؛ ثبت دستی کد رهگیری. اتصال API شرکت‌های حمل در نسخهٔ ۱ نیست.
- **مرجوعی و بازپرداخت:** درخواست مشتری، تأیید ادمین، برگشت کالا به انبار، بازپرداخت از درگاه یا دستی؛ مهلت انصراف قابل تنظیم (۱۴ روز برای اروپا).
- چرخهٔ عمر سفارش با تاریخچه؛ چک مالکیت در همهٔ عملیات؛ ایمیل چندزبانه (و پیامک در صورت فعال بودن)؛ اعلان PWA (Web Push) اختیاری.

## فاز ۸ — ارز و درگاه‌های پرداخت ⬜

- تنظیمات ارز و درگاه مدیر سیستم (جدول بالا).
- `IPaymentGateway` (Strategy): Stripe، PayPal، زرین‌پال، سداد، به‌پرداخت ملت.
- نرخ تبدیل ارز: ورود دستی توسط مدیر، قاعدهٔ گرد کردن برای هر ارز، ثبت نرخ استفاده‌شده روی هر سفارش.
- تأیید فقط سمت سرور (Verify/Webhook با بررسی امضا)، Idempotency، ثبت تراکنش، بازپرداخت.

## فاز ۹ — حسابداری ⬜

- دفتر کل دوطرفه، سرفصل حساب‌ها، سند خودکار از فروش/پرداخت/بازپرداخت/خرید/تعدیل انبار؛ حسابداری چندارزی.
- هزینه‌ها، صندوق/بانک؛ گزارش سود و زیان، فروش، مالیات، ارزش موجودی؛ خروجی Excel/PDF؛ اسناد قطعی غیرقابل ویرایش.

## فاز ۱۰ — پنل مدیریت و گزارش‌ها ⬜

- داشبورد، مدیریت کاربران و نقش‌ها، تنظیمات فروشگاه/ارز/درگاه/پیامک/روش ورود/قالب، **لاگ ممیزی**.
- صفحات قانونی قابل ویرایش: قوانین، حریم خصوصی، بنر رضایت کوکی (اروپا)، Impressum (آلمان)، جای نماد اعتماد/اینماد (ایران).
- آمار فروش و بازدید داخلی و حافظ حریم خصوصی؛ GTM/GA4، Meta Pixel، Matomo اختیاری و **فقط پس از رضایت کاربر** (Consent Mode v2)؛ dataLayer استاندارد رویدادهای فروشگاهی.
- ثبت `utm_*` و ارجاع‌دهنده روی سفارش و گزارش فروش بر اساس کمپین/کانال؛ گزارش عبارات جستجو و 404ها؛ مدیریت Redirect.
- **فیدهای محصول:** Google Merchant Center، Meta Catalog، ترب، ایمالز (پشت `IProductFeed`).
- خبرنامه با Double opt-in، ایمیل «موجود شد» و «کاهش قیمت». فرم تماس و پیام روی سفارش؛ چت آنلاین در نسخهٔ ۱ نیست.

## فاز ۱۱ — کارایی، SEO و سخت‌سازی امنیتی ⬜

- کش (Output cache، ISR در Next.js)، فشرده‌سازی، کوئری‌های بهینه؛ هدف **Lighthouse ≥ 90** در موبایل.
- ممیزی کامل با [چک‌لیست پذیرش SEO](SEO-MARKETING.md#چک‌لیست-پذیرش-هر-صفحهٔ-عمومی)، اعتبارسنجی JSON-LD و فیدها، ثبت در Google Search Console؛ دسترس‌پذیری WCAG AA؛ چک‌لیست OWASP Top 10 و تست نفوذ پایه (OWASP ZAP).

## فاز ۱۲ — پایگاه‌های دادهٔ دوم، مستندات و انتشار ⬜

- Migrationهای **SQL Server** و **MySQL** و اجرای تست‌های یکپارچه‌سازی روی هر سه.
- `docs/user-guide`، `docs/admin-guide`، `docs/sysadmin-guide` (نصب لینوکس/ویندوز، تنظیمات، پشتیبان‌گیری PostgreSQL، به‌روزرسانی، مانیتورینگ) به فارسی و انگلیسی.
- **پشتیبان‌گیری و به‌روزرسانی هر نصب:** `pg_dump` زمان‌بندی‌شده + پشتیبان فایل‌های رسانه، تمرین بازیابی؛ پیش از هر به‌روزرسانی پشتیبان خودکار و سپس Migration؛ اسکریپت به‌روزرسانی برای همهٔ نصب‌ها.
- راهنمای ایمیل (SPF/DKIM) و راهنمای قانونی برای فروشنده: انطباق مالیاتی (مودیان، VAT، e-HDM) بر عهدهٔ فروشنده است.
- انتشار نسخهٔ ۱.۰.

اتصال API شرکت‌های حمل، امتیاز وفاداری و کارت هدیه، ایمیل سبد رهاشده، چت آنلاین، ترجمهٔ ماشینی، پلتفرم SaaS چندفروشگاهی.
